# 防回归清单（派活 / 回执 / 自检）

> 目的：多会话、多轮时"本来正确的被顺手改回错"。这页是可套用的模板；配套 hub-ops §十二。

## A. 派活用（中枢 → worker）

在「本次只做」之外，补一段"保持不动"：

```text
本次只做：
- …（要改的 1~2 条）

保持不动（不变量，改坏就打回）：
- …（既有正确项 1：某个行为 / 数值 / 已修 bug）
- …（既有正确项 2）
范围外的问题写进结论，不要顺手改。
```

## B. 回执用（worker → 中枢）

```text
status: done
done: [本轮真正做完的]
回归确认：
- 不变量 X 已确认未变（怎么验：…）
- 不变量 Y 已确认未变（…）
非预期改动：无 / 有（逐条列出）
```

## C. 自检（改完、提交前）

1. `git status --short` / `svn status`：改动集合必须 **⊆ 计划改的路径**；出现计划外路径 = 可能顺手改坏 → 圈出来（见 `防回归自检.ps1`）。
2. 编译 / 类型检查（如 `tsc -p ...`）**0 error**。
3. 逐条复验「不变量」——有条件的跑脚本 / 截图取证，别只看文字。
4. 结论与提交号回填**唯一事实源**（如 `memory/STATUS.md`），不要在多个文档各写一份（会漂移）。

## D. 判"是不是真回归"

- 先以权威源核对**当前值**，再判定；别凭"感觉以前是对的"就回退。
- 常见误判：**以为是"被覆盖"，其实是"从未实现"**（历史里真出现过）。先查清再动手。
- 确认是回归：用 `git blame` / `svn log` / 轮次记录找出**哪一轮、谁**改的，再改，避免又盖回去。

## E. 记录纪律（防"下一轮基于错状态"）

- 轮次号、文件名、STATUS 里的编号必须一致；编号漂移会让下一轮按错状态再改一遍。
- 同一"事实/结论"只保留一处权威（STATUS 为准），别处只引用。
